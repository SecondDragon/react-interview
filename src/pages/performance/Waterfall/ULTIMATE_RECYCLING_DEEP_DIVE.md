# Ultimate 级瀑布流：DOM 节点复用架构深度解析

## 1. 架构目标：消灭 Mount/Unmount
在基础虚拟列表中，我们通过 `return null` 来移除不可见的元素。虽然减少了 DOM 节点，但在高速滚动时，React 必须频繁地：
1.  **销毁（Unmount）** 顶部的旧节点。
2.  **创建（Mount）** 底部的新节点。

这种频繁的 DOM 操作会导致 **GC（垃圾回收）抖动** 和 **主线程执行波峰**。
**Ultimate 方案的目标是：DOM 数量恒定，仅更新 Props。**

---

## 2. 核心支柱：节点池 (Slot Pool)

### A. 编制固定化
我们不再根据 `dataList` 来循环渲染，而是根据一个固定大小的 `POOL`（例如 60 个槽位）来渲染。
```tsx
const POOL_SIZE = 60;
// ...
{displayPool.map((slot, slotIdx) => (
  <div key={`slot-${slotIdx}`}>...</div>
))}
```
**为什么这么做？**
React 的 Diff 算法是基于 `key` 的。当 `key` 保持为 `slot-0`, `slot-1` 时，React 认为组件实例从未改变。滚动时，卡片发生的不是“重生”，而是“位置平移”和“内容换肤”。

### B. 槽位指派算法 (Recycling Logic)
如何决定数据 `#105` 该用哪个槽位展示？
我们使用最简单的**取模算法**：`slotIdx = dataIdx % POOL_SIZE`。
- 数据 `#5` 占据 `Slot #5`。
- 数据 `#65` 进入视口时，如果数据 `#5` 已经滑出视口，那么 `Slot #5` 就会被重新指派给数据 `#65`。

---

## 3. 性能深度优化 (GPU & Layout)

### A. 3D 瞬移 (No Transitions)
在 `Ultimate` 版本中，我们彻底移除了 `transition`：
- **原因**：当 `Slot #5` 从 `top: 100px` 瞬移到 `top: 5000px` 时，如果有 `transition`，你会看到卡片像流星一样从屏幕划过，造成剧烈闪烁。
- **解决**：使用 `translate3d` 瞬间到位。

### B. 硬件加速 (Compositing)
通过 `will-change: transform`，我们告诉浏览器为这 60 个槽位各分配一个 **GPU 层**。
这样在滚动时，浏览器只需移动显存里的“图块”，而不需要重新计算布局。

---

## 4. 常见问题 (Caveats)

1.  **图片残留**：如果新数据加载慢，Slot 可能还显示着旧数据的图。
    *   *方案*：在指派新数据时，可以先显示骨架屏颜色块。
2.  **私有状态丢失**：组件内部的 `useState` 会在复用时被污染。
    *   *准则*：复用组件必须是 **“纯组件”** 或 **“受控组件”**，所有状态（如点赞、评论数）必须从数据源 `props` 传入。

---

## 5. 学习路线
1.  **观察 DOM**：打开 F12，盯着容器内部。你会发现节点数量死死不动，只有 `transform` 的数值在跳动。
2.  **性能对比**：在性能极差的设备上，Ultimate 版的滚动曲线会比 Pro 版更加平滑。

---
*本技术方案参考了业界主流 Recycler View 实现，是前端长列表性能优化的终极形态。*
