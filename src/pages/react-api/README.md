# React API 学习专题

## 专题概述

本专题用于系统性地学习 React 的各个 API 的用法，以及探索一些在日常开发中较为少见但非常实用的 "Hack" 级用法。

## 内容组织方式

### 1. 目录结构

每个 API 的学习都是一个**单独的文件夹**，文件夹内包含该 API 相关的所有案例与说明文件：

```
src/pages/react-api/
├── README.md                  # 本前提文档
├── index.tsx                  # 专题入口页面
├── useState/                  # useState API 学习文件夹
│   ├── Examples.ts            # 案例元数据（Bad/Good Code、原理简述等）
│   └── index.tsx              # 案例展示组件
├── useRef/                    # useRef API 学习文件夹
│   ├── Examples.ts
│   └── index.tsx
└── ...
```

### 2. 页面结构规范

每个 API 的学习页面遵循以下结构：

1. **API 名称与简介**：明确当前学习的 API 是什么，以及它的核心作用。
2. **API 的基础用法**：展示该 API 最标准、最常见的使用方式。
3. **API 的进阶 / 特定用法**：展示一些较为少见但非常有用的用法（Hack 用法）。
4. **每种用法**都作为一个章节，必须有独立的Live Demo 互动演示
5. **Live Demo 互动演示**：通过可交互的示例让用户直观感受不同用法的差异。
6. **api实现原理**:在篇章最后要给出这个api的实现原理，是基于哪些技术，特别是它是基于react的那些底层原理实现的，这部分展示可以使用文档和源码举例的方式进行展示，且必须是一个单独的组件

### 3. 案例展示规范

- **每个案例都必须包含真实的 Demo 展示**：仅有代码片段是不够的，每个案例都需要配合一个可交互的、真实运行的 Demo 组件，让用户能够亲手操作并直观感受 API 的行为与差异。
- 每个 API 文件夹内的**各种案例统一放入 Collapse（折叠面板）组件**中进行展示，折叠面板的title是对该案例的简介。
- 当某个 API 下存在**多个案例时，默认展开前三个**，其余保持折叠状态，以节省页面空间。
- 如果有代码对比的话优先使用 `CodeDiff` 组件展示 "反面教材 (Bad Practice)" 与 "最佳实践 (Best Practice)"。
- 当我要求对某种用法增加某种特殊的案例时，你要做的是增加案例，而不是对之前已有的进行修改
- 所有代码注释及文档解释必须使用**中文**。

### 4. 页面布局规范

- **页面宽度应自适应路由页面宽度**：专题页面及各个 API 学习页面的根容器不应设置 `max-width` 或 `margin: 0 auto` 等限制宽度的样式，应充分利用外层 `Content` 布局容器提供的可用空间。
- 外层布局（`MainLayout`）已提供统一的内边距，各专题页面内部仅需保持简洁，避免额外添加会收窄内容区域的包裹样式。

### 5. 命名规范

- 文件夹名应与 API 名称保持一致（如 `useState`、`useEffect`、`forwardRef` 等）。
- 元数据文件统一命名为 `Examples.ts` 或 `Examples.tsx`，确保在按字母排序时与 `index.tsx` 相邻。
