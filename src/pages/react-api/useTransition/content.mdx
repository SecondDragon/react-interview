## 章节一：基础用法 <Tag color="blue">startTransition</Tag>

<Card title="一、用法意图" style={{ marginBottom: '16px' }}>
  <Typography.Paragraph>
    当某个状态更新会导致大量重渲染、阻塞用户输入或动画时，可以把它放进 startTransition，让 React 先保证高优先级交互的流畅。
  </Typography.Paragraph>
  <Alert
    message="核心原则"
    description="受控输入等需要即时反馈的状态必须同步更新；只有依赖输入结果的过滤、搜索、视图切换才适合放入 transition。"
    type="info"
    showIcon
  />
</Card>

<Card title="二、底层原理" style={{ marginBottom: '16px' }}>
  <Typography.Paragraph style={{ whiteSpace: 'pre-wrap' }}>
    React 18 的并发渲染允许更新拥有优先级。startTransition 会把内部的 setState 标记为 TransitionLane，优先级低于输入事件（InputDiscreteLane）和动画帧。因此即使用户继续输入，React 也会先完成输入响应，再抽空渲染 transition。
  </Typography.Paragraph>

## 章节五：实现原理 <Tag color="gold">并发渲染</Tag>

<Card title="一、原理总览" style={{ marginBottom: '16px' }}>
  <Typography.Paragraph>
    要理解 useTransition，必须先理解 React 18 的并发渲染模型。它由三个核心概念支撑：并发更新、时间切片和 Lane 优先级模型。
  </Typography.Paragraph>
</Card>

<Card title="二、核心概念" style={{ marginBottom: '16px' }}>
  <List
    dataSource={[
      {
        title: '并发更新（Concurrent Updates）',
        content:
          'React 18 之前，一次渲染一旦开始就必须完成，无法中断。React 18 引入了并发渲染，允许 React 在执行低优先级更新时，暂停当前工作去处理更高优先级的更新，然后恢复或丢弃之前的工作。',
      },
      {
        title: '时间切片（Time Slicing）',
        content:
          'React 把一次长渲染拆分成多个小任务（通常约 5ms），每个切片执行完后会检查是否有更高优先级任务。如果有，就暂停当前工作；如果没有，就继续下一个切片。这样主线程不会被长时间占用。',
      },
      {
        title: 'Lane 模型',
        content:
          'React 用 Lane（二进制位）表示更新的优先级。InputDiscreteLane（输入事件）优先级高于 TransitionLane。startTransition 会把更新标记到 TransitionLane，因此输入事件可以插队，旧的 transition 会被丢弃并基于最新状态重新调度。',
      },
    ]}

<Card title="三、startTransition 的优先级注入机制" style={{ marginBottom: '16px' }}>
  <Typography.Paragraph>
    要理解 <Typography.Text code>startTransition</Typography.Text> 如何让 <Typography.Text code>HeavyList</Typography.Text> 变"低优先级"，需要追踪一条从 API 到底层 Lane 再到 Scheduler 调度器的完整链路。
  </Typography.Paragraph>

  <Typography.Title level={5}>第一步：设置上下文标志</Typography.Title>
  <Typography.Paragraph>
    当用户代码调用 <Typography.Text code>startTransition(() =&gt; setSearchQuery("数"))</Typography.Text> 时，React 不会立刻分析 <Typography.Text code>setSearchQuery</Typography.Text> 的优先级，而是先做一个动作：<Typography.Text strong>设置一个全局上下文变量</Typography.Text>。
  </Typography.Paragraph>
  <pre style={{ fontSize: 13, fontFamily: 'monospace', lineHeight: 1.8, padding: '12px 16px', background: '#f6f8fa', borderRadius: 4, overflow: 'auto' }}>
{`function startTransition(scope) {
  const prevTransition = ReactCurrentBatchConfig.transition;
  ReactCurrentBatchConfig.transition = { name: 'Pending' };
  try {
    scope();  // 执行你的回调
  } finally {
    ReactCurrentBatchConfig.transition = prevTransition;
  }
}`}
  </pre>
  <Typography.Paragraph>
    <Typography.Text code>ReactCurrentBatchConfig.transition</Typography.Text> 是一个模块级全局变量。不处于 transition 时为 <Typography.Text code>null</Typography.Text>，处于 transition 中时为 <Typography.Text code>{`{ name: 'Pending' }`}</Typography.Text>。<Typography.Text strong>所有 setState 的底层函数在申请优先级时都会检查这个变量。</Typography.Text>
  </Typography.Paragraph>

  <Typography.Title level={5}>第二步：requestUpdateLane 的分叉逻辑</Typography.Title>
  <Typography.Paragraph>
    <Typography.Text code>setSearchQuery("数")</Typography.Text> 最终会调用 <Typography.Text code>dispatchSetState</Typography.Text>，其核心是 <Typography.Text code>requestUpdateLane(fiber)</Typography.Text>：
  </Typography.Paragraph>
  <pre style={{ fontSize: 13, fontFamily: 'monospace', lineHeight: 1.8, padding: '12px 16px', background: '#f6f8fa', borderRadius: 4, overflow: 'auto' }}>
{`function requestUpdateLane(fiber) {
  if (!(fiber.mode & ConcurrentMode)) return SyncLane;

  // ★★★ 核心判断 ★★★
  const transition = ReactCurrentBatchConfig.transition;
  if (transition !== null) {
    return claimNextTransitionLane();  // → TransitionLane
  }

  const currentEventLane = currentEventLane;
  if (currentEventLane !== NoLane) {
    return currentEventLane;  // → InputDiscreteLane
  }

  return SyncLane;
}`}
  </pre>
  <Alert
    type="info"
    message="同一个事件回调中两个 setState 获得不同优先级"
    description="startTransition 外部的 setInputValue 不在 scope 内部，requestUpdateLane 读到的是 currentEventLane（来自 React 事件系统注入的 InputDiscreteLane）。而 scope 内的 setSearchQuery 读到的是被设为 { name: 'Pending' } 的 ReactCurrentBatchConfig.transition → TransitionLane。"
    showIcon
    style={{ marginBottom: 16 }}
  />

  <MermaidViewer source={priorityInjection} lazy />

  <Typography.Title level={5}>第三步：TransitionLane → Scheduler 优先级的映射</Typography.Title>
  <Typography.Paragraph>
    <Typography.Text code>scheduleUpdateOnFiber(root, TransitionLane)</Typography.Text> 需要把 Lane 转成 Scheduler 包认识的优先级数字：
  </Typography.Paragraph>
  <pre style={{ fontSize: 13, fontFamily: 'monospace', lineHeight: 1.8, padding: '12px 16px', background: '#f6f8fa', borderRadius: 4, overflow: 'auto' }}>
{`function lanesToSchedulerPriority(lanes) {
  if (includesSyncLane(lanes))
    return ImmediatePriority;         // 同步，立刻执行
  if (includesInputDiscreteLanes(lanes))
    return UserBlockingPriority;      // 250ms 超时
  if (includesTransitionLanes(lanes))
    return NormalPriority;            // ★ 5000ms 超时
  return IdlePriority;
}`}
  </pre>
  <Typography.Paragraph>
    这里的"低优先级"的含义就是：这个任务被放在 Scheduler 任务队列的 <Typography.Text code>NormalPriority</Typography.Text> 位置，前面还有 <Typography.Text code>ImmediatePriority</Typography.Text>（同步）和 <Typography.Text code>UserBlockingPriority</Typography.Text>（250ms）的任务等着。只有当主线程空闲、没有更高优先级的任务时，才会轮到它执行。
  </Typography.Paragraph>

  <Typography.Title level={5}>第四步：renderLanes 透传时的 Update 过滤</Typography.Title>
  <Typography.Paragraph>
    当 Scheduler 决定执行 <Typography.Text code>performConcurrentWorkOnRoot</Typography.Text> 后，React 计算出本轮要处理的 <Typography.Text code>renderLanes</Typography.Text>，然后在 <Typography.Text code>processUpdateQueue</Typography.Text> 中做位运算匹配：
  </Typography.Paragraph>
  <pre style={{ fontSize: 13, fontFamily: 'monospace', lineHeight: 1.8, padding: '12px 16px', background: '#f6f8fa', borderRadius: 4, overflow: 'auto' }}>
{`function processUpdateQueue(fiber, queue, renderLanes) {
  let update = queue.firstUpdate;
  while (update !== null) {
    // ★★★ 只处理与 renderLanes 匹配的 update ★★★
    if (isSubsetOfLanes(update.lane, renderLanes)) {
      newState = computeUpdate(newState, update.action);
    }
    // 不匹配的 update 跳过，留到下一轮
    update = update.next;
  }
  return newState;
}`}
  </pre>

  <Typography.Title level={5}>第五步：输入事件插队时丢弃旧工作</Typography.Title>
  <Typography.Paragraph>
    当渲染过程中有新输入事件触发时，<Typography.Text code>scheduleUpdateOnFiber(root, SyncLane)</Typography.Text> 被调用。<Typography.Text code>ensureRootIsScheduled()</Typography.Text> 检测到 root 有 SyncLane 待处理，立即中断当前 transition 渲染：
  </Typography.Paragraph>
  <pre style={{ fontSize: 13, fontFamily: 'monospace', lineHeight: 1.8, padding: '12px 16px', background: '#f6f8fa', borderRadius: 4, overflow: 'auto' }}>
{`function prepareFreshStack(root) {
  rootFiber = root.current;
  workInProgress = createWorkInProgress(rootFiber, null);
  // ↑ workInProgress 被全新创建
  // 旧的 workInProgress 不再被引用 → GC 回收
}`}
  </pre>
  <Typography.Paragraph>
    这就是"丢弃旧工作"的源码级含义——旧的 WIP 树（基于 <Typography.Text code>searchQuery = "数"</Typography.Text>）变成孤儿被 GC 回收。同步渲染完成后，新的 TransitionLane 任务被重新调度，这一次 <Typography.Text code>HeavyList({`{ query: "数据" }`})</Typography.Text> 基于最新的搜索词运行。
  </Typography.Paragraph>
