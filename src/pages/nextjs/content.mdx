# Next.js 专题：与普通 React 开发的全面区别

> 如果你只写过 CRA (Create React App) 或 Vite 搭建的 React SPA，第一次接触 Next.js 时很可能会感到困惑："同样是 React，为什么写法完全不同？" 本专题将系统性地梳理 Next.js 与传统 React 开发在**渲染模式、路由、数据获取、打包、部署**等各个维度的根本差异，并揭示背后的设计原理。

<Card style={{ marginBottom: 24 }}>
  <Typography.Title level={5}>什么是 Next.js？</Typography.Title>
  <Typography.Paragraph>
    Next.js 是 Vercel 公司维护的 **React 全栈框架**。它不是一个"React 加强版"，而是一个**在 React 之上构建的 Web 应用框架**，提供了传统 React SPA 不具备的**服务端能力**。
  </Typography.Paragraph>
  <Typography.Paragraph>
    可以把关系理解为：**React 是 UI 库（提供组件模型），Next.js 是应用框架（提供路由、渲染、数据获取、构建优化等完整方案）**。
  </Typography.Paragraph>
</Card>

## 一、根本原因：CSR 到 SSR 的范式转换

<Typography.Paragraph>
  要理解 Next.js 和普通 React 开发的所有区别，首先要抓住最核心的一个转变：**从纯客户端渲染（CSR）到服务端渲染（SSR）的范式转换**。这个转变是一切的根源。
</Typography.Paragraph>

<Card style={{ marginBottom: 24 }}>
  <Typography.Title level={5}>普通 React SPA（CSR）的渲染流程</Typography.Title>
  <Typography.Paragraph>
    1. 浏览器请求 `index.html`
  </Typography.Paragraph>
  <Typography.Paragraph>
    2. 服务器返回一个**几乎为空的 HTML**：`<div id="root"></div>` + `<script src="/bundle.js"></script>`
  </Typography.Paragraph>
  <Typography.Paragraph>
    3. 浏览器下载并执行整个 JS Bundle（可能几百 KB）
  </Typography.Paragraph>
  <Typography.Paragraph>
    4. JS 执行 `ReactDOM.createRoot().render()`，在客户端渲染所有内容
  </Typography.Paragraph>
  <Typography.Paragraph>
    5. 用户**必须等待 JS 下载→解析→执行完成**后才能看到页面内容
  </Typography.Paragraph>
</Card>

<Card style={{ marginBottom: 24 }}>
  <Typography.Title level={5}>Next.js（SSR）的渲染流程</Typography.Title>
  <Typography.Paragraph>
    1. 浏览器请求 `/some-page`
  </Typography.Paragraph>
  <Typography.Paragraph>
    2. **Next.js 服务器在 Node.js 中运行 React 组件**，将其渲染为完整的 HTML 字符串
  </Typography.Paragraph>
  <Typography.Paragraph>
    3. 服务器返回**包含完整内容的 HTML**（标题、段落、图片等都已渲染好）
  </Typography.Paragraph>
  <Typography.Paragraph>
    4. 浏览器直接展示 HTML（用户**立即看到内容**）
  </Typography.Paragraph>
  <Typography.Paragraph>
    5. 浏览器后台下载 JS Bundle，执行 **Hydration**（为静态 HTML 绑定事件处理器）
  </Typography.Paragraph>
</Card>

<Typography.Paragraph>
  这个**核心流程的差异**导致了后面所有的不同：路由系统、数据获取方式、打包策略、部署方式、SEO 能力……一切都围绕着"代码需要在服务端运行"这个前提展开。
</Typography.Paragraph>
