库 API

TanStack Table

useReactTable()

核心 Hook，接收 data + columns + 状态，返回 table 实例
{ data, columns, state, getCoreRowModel }
TanStack Table

table.getRowModel()

返回 { rows: Row[] }，包含所有数据行的完整模型
→ { rows: [{ id, getVisibleCells, getIsSelected }] }
TanStack Table

table.getHeaderGroups()

返回表头分组，每组包含 headers 数组
→ [{ id, headers: [{ id, getSize, column }] }]
TanStack Table

table.getTotalSize()

所有列的宽度之和（用于设置 table 宽度）
→ number
TanStack Table

flexRender()

通用渲染器：如果传函数则调用，否则直接渲染
flexRender(header, ctx) → ReactNode
TanStack Table

ColumnDef

列定义类型：id, accessorKey, header, cell, size
{ id, accessorKey, size, header?, cell? }
TanStack Virtual

useVirtualizer()

核心 Hook，计算哪些行应在视口内渲染
{ count, getScrollElement, estimateSize, overscan }
TanStack Virtual

getVirtualItems()

返回当前应渲染的虚拟行数组
→ [{ key, index, start, end, size }]
TanStack Virtual

getTotalSize()

总内容高度 = count × estimateSize（撑滚动条用）
→ number
TanStack Virtual

estimateSize

预估行高函数 (index) → number，非实际高度
(index: number) => number
TanStack Virtual

overscan

视口外额外渲染的像素数（缓冲区，防白屏）
number（像素，非行数）

CSS 关键概念

CSS

position: sticky

元素在滚动容器内固定在指定位置。定位父级是最近的 overflow ≠ visible 的容器
sticky + top: 0 → 紧贴容器顶部
CSS

transform: translateY()

CSS 变换，只触发 Composite（合成），跳过 Layout + Paint
translateY(n px) → GPU 加速
CSS

Stacking Context

层叠上下文。非 fully opaque 的 position 元素、transform 都创建它
transform → 新 Stacking Context
CSS

table-layout: fixed

固定表格布局，列宽由第一行（thead）决定，而非内容撑开
fixed → 列宽由 th 的 width 决定
CSS

will-change

提示浏览器提前优化指定属性，可能创建合成层
will-change: transform
CSS

isolation: isolate

创建新的 stacking context，隔离子元素的层叠
isolation: isolate → 新 context

渲染机制

概念说明性能影响
Layout（重排）计算元素几何信息（位置、大小）CPU 密集，触发整个子树
Paint（重绘）将像素填充到位图上中等，受绘制区域影响
Composite（合成）在 GPU 将各图层合并最快，不涉及 CPU
合成层被提升到独立图层的元素GPU 处理，大幅减少绘制

工作中遇到的 Bug

Sticky Header 穿透

现象

上滑时，虚拟行内容在 sticky thead 背后隐约可见

根因

1) Chrome table sticky 实现缺陷；2) thead background 覆盖不完整；3) 虚拟行 transform 创建新 stacking context 导致绘制顺序异常

修复

thead { transform: translateZ(0); } 提升到 GPU 层；或在 thead 上增加 isolation: isolate
